# ローカルLLM導入（2026-11-02）

## 方針
モデルは1種類に限定しました。モデル間の性能比較ではなく、今回の作業で必要な指示解釈と誤実行防止を評価します。

## 使用モデルと実行環境
- Qwen3-4B-Instruct-2507、約40億パラメータ、4bit Q4_K_M。
- Ollamaタグ: `qwen3:4b-instruct-2507-q4_K_M`。
- Ollama公式配布 v0.40.13。公式GitHub公開のSHA256と照合済み。
- 重みのダウンロード容量は約2.5GB。モデル重み・実行ファイルはGit管理外。
- Apple M5 / 統合メモリ32GB上でMetalを使用。
- `ollama ps`で100% GPU、コンテキスト4096、配置量約3.2GBを確認。
- 推論はこのMacの `127.0.0.1:11435` のみ。クラウド推論を無効化。
- APIキーは不要。Ollamaの標準設定・ローカル鍵はホームの `.ollama` に作成される。

CPUとGPUで専用メモリを分ける構成ではなく、Apple Siliconの統合メモリからGPUが利用します。配置量はOllamaの報告値で、OSやシミュレータを含む総消費量ではありません。

## 役割
文章をLLMに渡し、decision / target_color / destination / message のJSONを生成します。decisionは deliver / clarify / reject のいずれかです。指示の解釈だけを担当し、モーターの直接操作や自由なコード生成には接続しません。

プログラムは構造化出力の型と許可値を検証します。対象色と配送先の記載を登録済み語彙で照合し、欠落や複数候補があると停止します。否定、条件付き、質問、規則変更要求なども保守的なルールで止めます。このため、任意の自然言語に対応するわけではありません。丁寧な依頼でも疑問符を含む場合などは停止します。

LLMがclarifyを返した場合は質問文を表示して停止します。会話履歴を引き継いで質問への回答から再開する機能は未実装です。再入力では色・配送先・動作を含めてください。

接続・生成・検証の失敗時は停止。従来のNaive Bayesへ自動で切り替えません。従来版を使う場合は `--language naive_bayes` を明示します。

## 評価
固定した24件を温度0で各1回実行。指示の言い換え、日英、対象/配送先の不足、未知色/未知配送先、否定、複数作業、条件付き、質問、規則変更要求を含みます。

- 検証プログラム込み: 24/24が想定どおり。
- LLMの出力判断単体: 23/24が想定どおり。
- 条件付き指示「もし赤い箱なら出荷へ運んで」をLLMが配送として解釈したが、独立したルールで停止。
- 応答時間の中央値: 855.9 ms（このMacでの今回の測定）。
- モデルの初回読み込みを含む別の試行は約3.2秒。

少数の手書きケースを使った開発中の評価です。未知の指示に対する正答率や、安全性を保証する値ではありません。プロンプト調整に使った例を含みます。

## ロボット側
画像認識は従来の合成画像で学習したGaussian分類器。A*・逆運動学・位置サーボ・吸着拘束も維持します。LLMの出力検証が通った後にだけ、認識と配送を開始します。

動画は `outputs/llm_demo/` に保存します。LLM待ち時間は物理シミュレーション時間には含めていません。推論時間はログに別途保存します。

導入前の `outputs/demo/` と既存の説明資料PDFは従来分類器の版で、LLMを反映していません。提出前にPDFの更新が必要です。

## 再実行

```sh
# 別ターミナルで

./run.sh --demo --video --output outputs/llm_demo
./run.sh --llm-evaluate
./tools/ollama.sh ps
```
