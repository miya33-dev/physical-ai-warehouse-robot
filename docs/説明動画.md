# LLMとA*の処理が見える動画

## 実行
ローカルLLMサーバーを起動し、学習済み検出器を準備した環境で実行します。

```sh
./tools/start_llm.sh
# 別ターミナル
./run.sh --demo --layout-seed 0 --distractors --video --video-speed 2 --explain-video --output outputs/explanatory_demo_hd
```

`--explain-video` を省略すると従来の動画形式です。同じ出力先は上書きされます。

## 画面の読み方
- 左上：MuJoCoの3D物理シミュレーション。指でつかみ、車輪で運ぶ様子。
- 右上：真上の全体カメラ画像と経路探索。Sは台車の出発位置、Gは台車の目標位置です。荷物そのものの位置とは異なります。
- 左下：Qwen3 4Bが実際に返した decision / target_color / destination / message のJSON。内部の思考過程ではありません。Python側の検証後、認識・制御へ渡します。
- 右下：YOLOの予測枠、クラス、スコアと推定座標。把持・配置時は指先の映像へ切り替わります。

A*は10cmの格子、上下左右の4近傍で探索します。gは出発点からの移動コスト、hは目標までのマンハッタン距離、f=g+hです。いずれも格子の歩数に相当します。

| 色 | 表示内容 |
| --- | --- |
| 青 | 探索で取り出した格子 |
| 紫 | 探索候補として追加され、まだ探索済みでない格子 |
| オレンジ | 既知の中央障害物を安全余裕0.53mで拡張した領域 |
| 黄 | A*で求めた台車の計画経路 |
| 緑 | シミュレータから記録した台車の実走行軌跡 |

赤い荷物への接近、発送先への配送、青い荷物へ戻る接近、保管先への配送の計4回を表示します。各探索は実際のヒープからの取り出し・候補追加ログを38フレーム（約2.53秒）で再生します。その間は物理時間を進めません。探索の実測計算時間ではありません。物理動作部分は約2倍速です。

## 前提と制約
上空画像に探索を重ねていますが、障害物の地図を画像認識から作っているわけではありません。経路探索は中央障害物と走行範囲の既知地図を使います。配送台・荷物台全体を占有格子に変換する処理はありません。自己位置もシミュレータから取得します。YOLOはRGB画像から荷物を検出し、既知のカメラと高さから座標へ変換します。

この変更は表示とログの追加です。経路探索の優先度、車輪・アーム・把持の制御や学習済みモデルは変更していません。

## 保存される記録
- `demo.mp4`：1920×1080、15fpsの説明動画。
- `preview.png`：動画生成中のプレビュー。
- `results.json`：実際のLLM応答、認識、配送成否、接触等の結果。
- `planning.json`：探索時の取り出し・候補追加ログ、計画経路、実走行軌跡。

14件の単体テストに、ログ取得の有無で経路が変わらないことと、上空画像の床面投影の軸方向の検証を含みます。動画・ログは生成物としてGit管理外です。

## 今回の生成結果
`outputs/explanatory_demo_hd/demo.mp4` は149.13秒、1920×1080、15fpsです。赤・青の2件とも配送成功、中央障害物と台車・台の接触検出は0でした。4経路の探索ログ件数は順に4・379・156・378件です。記録された4経路を元の計画関数で再計算して一致を確認し、荷物の最終位置も表示追加前のYOLOデモと一致しました。完成動画から抜き出した画像でも表示を確認しました。
