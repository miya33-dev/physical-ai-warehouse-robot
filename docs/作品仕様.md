# 作品仕様

2026-11-02: 最小構成を実装・検証済み。実測結果は [実装と検証](実装と検証.md) を参照。

## テーマ
自然言語指示による倉庫内ピッキング・配送ロボット。
自然言語理解・画像認識・アーム操作・移動制御を、一連の作業として接続します。

## 最小構成
- 台車とロボットアームを組み合わせた移動マニピュレータ1台。
- 同じ形で色が異なる箱2個（赤・青）。
- 荷物の初期位置は既知の棚上の定位置。
- 配送先2か所（出荷場所・保管場所）。
- 固定障害物1個。既知の地図を使用。
- 指示形式は「赤い箱を出荷場所へ運んで」など。
- 初期版は荷物1個ずつ運ぶ。経路と把持姿勢の難易度を抑える。

## 処理の流れ
1. 文章を入力する。
2. AIが対象色と配送先を構造化する。
3. 許可された対象・配送先か検証する。不明なら動作を開始しない。
4. カメラ画像から対象の箱を認識する。
5. ピッキング位置へ移動・停止する。
6. アームを動かして箱を把持し、持ち上げる。
7. 障害物を考慮した経路を計画し、配送先まで移動する。
8. 箱を配置し、成功条件を確認する。

## AIの担当範囲
- 指示理解: ローカルLLM Qwen3-4B-Instruct-2507で単発指示をJSONへ変換し、独立した検証を通して実行。従来のNaive Bayesは明示指定で利用可能。詳細は「LLM導入.md」を参照。
- 画像認識: 合成画像の18,096画素で学習したGaussian分類器による赤・青・背景の分類。
- 移動: 最初はA*等の経路探索と通常の制御。強化学習は追加課題とする。
- アーム: 逆運動学と制御プログラムで動かす。

キーワード検索、色の閾値処理、A*だけを実装した場合、それらを学習済みAIの推論と説明しない。提出版には少なくとも1つ、実際に動くAI処理を組み込む。

## シミュレータ
MuJoCo 3.3.7を使用。PyBulletはこのMacでビルドに失敗したため採用を見送った。MuJoCoの物理・描画・MP4出力を確認済み。

## 完成条件
- 赤・青の箱について、それぞれ指定先へ配送できる。
- 指示と異なる箱を運ばない。
- 荷物の認識結果が画像入力に基づく。物体IDを直接読んだ結果を画像認識と呼ばない。
- 障害物を避け、ロボット本体・アーム・運搬中の荷物が障害物に衝突しない。
- 把持・運搬・配置の過程を動画で確認できる。
- 対象の箱がない場合、不明な配送先の場合は停止して理由を表示する。
- 各指示の成否と失敗理由をログに残す。

## 簡略化する場合の明記
台車位置の直接更新、吸着や固定拘束による把持、既知座標の使用を採用する場合は、動画・レポートに簡略化を明記する。物理的な接触把持や自律位置推定を実装したと説明しない。
